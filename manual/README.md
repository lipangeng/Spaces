# manual-space

[简体中文](README.zh-CN.md)

`manual-space` is a generic persistent Linux workspace for human-operated sessions. It inherits the complete runtime contract from [`space-base`](../base/README.md) without bundling an IDE, language runtime, notebook, or terminal service.

## Current scope

The initial image intentionally adds no packages or startup behavior beyond `space-base`. It provides a stable image name and extension point for interactive workspace deployments while keeping application choices outside the image.

Use the inherited facilities for customization:

- `/home/space` for user applications, shell configuration, mise runtimes, and application data.
- `/workspace` for repositories and other work products.
- `/entrypoint.d/user` for persistent user provisioning.
- `CMD`, Compose `command`, or Kubernetes `command` and `args` to select the interactive service.

## Build

`SPACE_BASE_IMAGE` is a required build argument. Build Base first, then pass the image reference produced by the first stage to `manual-space`:

```bash
SPACE_VERSION=1.0.0
BASE_IMAGE="ghcr.io/lipangeng/space-base:${SPACE_VERSION}"
docker build -t "${BASE_IMAGE}" ./base
docker build \
  --build-arg SPACE_BASE_IMAGE="${BASE_IMAGE}" \
  -t "ghcr.io/lipangeng/manual-space:${SPACE_VERSION}" \
  ./manual
```

In GitHub Actions, the first stage generates the Base image names and tags with Docker Metadata Action and publishes the image. The second stage must consume the complete image reference produced by the first stage. Prefer an immutable digest reference, for example:

```bash
docker build \
  --build-arg SPACE_BASE_IMAGE="ghcr.io/lipangeng/space-base@sha256:<digest>" \
  -t "<manual-space tag generated by docker/metadata-action>" \
  ./manual
```

## Run

Start the inherited Bash command with persistent storage:

```bash
docker run --rm -it \
  -v space-home:/home/space \
  -v "$(pwd)":/workspace \
  -v space-user-hooks:/entrypoint.d/user \
  ghcr.io/lipangeng/manual-space:1.0.0
```

An installed interactive application can be selected explicitly as the container command. Provisioning installs and configures the application; the command starts it.

```bash
docker run --rm \
  -v space-home:/home/space \
  -v "$(pwd)":/workspace \
  ghcr.io/lipangeng/manual-space:1.0.0 \
  code serve-web --host 0.0.0.0 --port 8000
```

The example assumes `code` has already been installed under the persistent user environment. `manual-space` itself does not install VS Code.

## Extension boundary

Add image-level dependencies to this image only when every manual workspace needs them. Prefer mise or `/home/space/.local` for user-selected software and user hooks for persistent host-level provisioning. See the [base documentation](../base/README.md) for entrypoint switches, hook semantics, and permission handling.
